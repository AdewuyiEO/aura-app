# Aura — Setup Guide

How to get the codebase running. This guide is split into **what runs today**
(verified) and **the full app setup** (the forward path once the UI shell is
scaffolded). Nothing here is aspirational unless labelled so.

---

## 1. Prerequisites

| Tool | Version | Needed for |
|---|---|---|
| Node.js | 18 LTS or 20 LTS | Everything |
| npm (or pnpm/yarn) | 9+ | Package install |
| Git | any | Clone |
| **For the full RN app (Phase 0 UI onward):** | | |
| Xcode | 15+ (macOS) | iOS simulator / device builds |
| Android Studio | Hedgehog+ | Android emulator |
| Expo CLI | via `npx expo` | Dev server, EAS builds |
| Watchman | latest (macOS) | File watching |

You do **not** need Xcode, Android Studio, or a simulator to run and verify the
core logic — see §3.

---

## 2. Get the code

```bash
unzip aura-app.zip        # or: git clone <your-repo>
cd aura-app
npm install
```

`npm install` pulls the small set of deps the logic layers need
(`zustand`, plus `tsx`/`typescript`/`react` for running tests). No native
toolchain required for this step.

## 5. Full app setup (forward path — the UI shell isn't scaffolded yet)

> **Status:** the domain + state + design-token layers are built. The Expo
> `app/` router and screens are specified (see `aura-v1.html` for a working
> reference of every screen) but not yet coded. These are the steps to stand up
> the shell and plug the existing layers in. `npx expo start` will not work until
> step 5.1 is done.

### 5.1 Create the Expo shell

```bash
# from a fresh dir, then move src/ in — or add expo to this package
npx create-expo-app@latest aura --template blank-typescript
cd aura
npx expo install expo-router react-native-safe-area-context \
  react-native-screens expo-linking expo-constants expo-status-bar
npx expo install react-native-reanimated react-native-gesture-handler \
  react-native-svg react-native-mmkv expo-haptics expo-image
npm install zustand
```

Then copy `src/domain`, `src/data`, `src/design` in, and set up `app/` with
expo-router (`app/_layout.tsx` hosts the ThemeProvider + tab navigator).

### 5.2 Reanimated config

Add to `babel.config.js`:

```js
module.exports = { presets: ['babel-preset-expo'], plugins: ['react-native-reanimated/plugin'] };
```

### 5.3 Run it

```bash
npx expo start          # press i (iOS) / a (Android)
```

MMKV works in a dev build (not Expo Go). Use `npx expo run:ios` or an EAS dev
build. The store's `persist.ts` falls back to in-memory if MMKV isn't present,
so early UI work can run in Expo Go before you make a dev build.

### 5.4 Backend (Phase 4 — not required for the alpha)

The app runs fully offline against the local repository. When you're ready:

```bash
# create a Supabase project, then:
# .env
EXPO_PUBLIC_SUPABASE_URL=https://xxxx.supabase.co
EXPO_PUBLIC_SUPABASE_ANON_KEY=xxxx
```

Apply `src/data/api/schema.sql`, add a Supabase implementation of the `Repo`
interface, and switch one line in the repo index. Nothing else changes — that's
what the repository seam buys you.

## 7. Troubleshooting

- **`Cannot find package 'zustand'/'react'`** when running tests → `npm install`.
- **`npx expo start` errors about a missing app dir** → the UI shell isn't
  scaffolded yet; see §5.1. The tests in §3 are what runs today.
- **MMKV crash in Expo Go** → expected; MMKV needs a dev build. The in-memory
  fallback keeps early UI work runnable in Go.
- **Reanimated "plugin" error** → add the babel plugin (§5.2) and clear the
  cache: `npx expo start -c`.
